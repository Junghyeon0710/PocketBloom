# 완료 여부와 남은 작업

전체 출시 목표는 아직 완료되지 않았습니다. 현재 상태는 광고 계정이 연결되지 않은 테스트 배포본입니다. 각 검사 시각은 Docs/Validation의 원본 기록에 있습니다.

| 요구사항 | 현재 증거 | 판정 |
|---|---|---|
| 2D 모바일 게임과 기획서 | PocketBloom 소스·씬, GameDesign.ko.md, 실제 에디터 화면 | 구현됨 |
| 콘텐츠와 규칙 | 36단계 승리 경로, 합법 배치 10,000수, UI 흐름·가상 터치 | 에디터 범위 통과 |
| 광고 보상 오류 처리 | EditModeTests-latest.xml, 규칙 8개와 보상 처리 5개 모두 통과 | 코드 경로 검증, 실제 광고 미검증 |
| Android 설치 파일 | Build-Android.json 성공, PocketBloom-test.apk 존재 | ARM64 IL2CPP 빌드 성공 |
| APK 구조와 서명 | ApkInspection.json, ApkSignature.txt, ApkZipAlignment.txt, ApkBadging.txt | debug v2 서명·16KB ELF/ZIP 정렬 통과, min API 26 / target API 36 |
| Windows 테스트 배포본 | Build-StandaloneWindows64.json, PocketBloom-Windows.zip | 오류 0개로 빌드 성공, 직접 조작 미검증 |
| 스토어 자료 | Docs/Store, StoreAssets.json | 배너·아이콘과 한·영 문구 준비, 크기·PNG 형식·문자 수 검사 통과. 단말 스크린샷·업로드 미완료 |
| 인앱결제 없이 광고로만 수익화 | IAP 미도입, LevelPlay 어댑터, enableAds=false | 실제 광고 미연결 |
| 실제 수익 및 시장 성과 | 출시·이용자·광고 수익 데이터 없음 | 미검증, 성과 보장 불가 |

APK 크기는 약 42MiB입니다. 정적 검사만으로 실제 휴대폰에서의 성능, 터치, 저장, 광고 동작을 확인했다고 판단하지 않습니다.

## 해결한 빌드 대기

기존 GUI 빌드는 PID 43460에서 대기했으며, 임의로 종료하지 않았습니다. 이후 해당 프로세스가 종료됐음을 확인하고 Unity CLI 배치 테스트와 Android 빌드를 실행했습니다. 테스트 13개와 Android 빌드가 성공했습니다. AndroidBuildWait.json은 해결 전의 과거 기록입니다.

## 남은 검증과 계정 정보

1. 현재 ADB에 연결된 Android 단말이 없으며, 사용자가 지금은 단말 테스트가 어렵다고 확인했습니다. APK 실제 설치, 물리적 터치, 앱 재시작 후 저장 복원, 노치·백그라운드·성능은 미검증입니다.
2. Windows 패키지 직접 조작 검증은 남아 있습니다. 에디터 플레이 화면은 Unity Recorder로 녹화했으며 실제 터치 입력·목표 달성·컬렉션·설정을 담은 하이라이트와 스크린샷을 [Docs/Media](Media/README.md)에 추가했습니다. 녹화 뒤 기존 프로필과 저장 파일 복원을 확인했습니다. 이 기록은 Android 단말 또는 Windows 패키지 직접 실행 검증과는 별도입니다.
3. 사용자가 광고 계정을 새로 만들어야 한다고 확인했습니다. LevelPlay Android App Key, Rewarded ID, Interstitial ID, 실제 개인정보처리방침 URL이 비어 있습니다. [광고 연결 가이드](AdsSetup.ko.md)에 등록 정보와 절차를 정리했습니다. CMP/동의 제공자를 연결한 뒤 광고를 활성화해야 합니다.
4. 실제 광고 완료·취소·표시 실패·오프라인 복귀·지연 콜백 및 이벤트 식별자를 단말에서 확인해야 합니다. 광고 콜백 코드 테스트 통과를 실제 광고 수익화 완료로 취급하지 않습니다.
5. 개발자 소유 서명, 출시 AAB, 스토어 등록과 비공개 테스트가 필요합니다. 현재 debug APK를 출시 서명으로 오인하지 않습니다.

## 다음 순서

계정 등록은 단말 없이 먼저 진행할 수 있습니다. 단말 확보 후 현재 APK 설치와 플레이 → 광고 계정·동의 제공자 연결 빌드 → 실제 광고 검증 → 출시 서명/AAB → 비공개 테스트와 소프트 론치 순서로 진행합니다. ReleaseChecklist.md는 각 증거가 생긴 항목만 완료 처리합니다.

## 외부 준비가 필요한 현재 지점

스토어 자료 제작 후 다시 확인해도 광고 앱 키·두 광고 단위 ID·정책 URL이 비어 있고, ADB 연결 목록도 비어 있습니다. 계정과 단말이 준비되지 않았다는 사용자 답변과 일치합니다. 기존 빌드·기획서·스토어 자료는 보존하며 전체 목표를 완료로 표시하지 않습니다.

이어 작업하려면 LevelPlay 계정의 앱 식별값, 확정된 대상 연령·배포 지역과 운영자 문의 정보가 필요합니다. 이를 바탕으로 실제 정책과 CMP를 연결한 새 빌드를 만들고, 사용 가능한 Android 단말에서 검증해야 합니다. 계정 비밀번호나 서비스 계정 Secret을 대화에 보낼 필요는 없습니다. 출시 서명과 스토어 등록은 그 이후 단계입니다.
