# 포켓 블룸 · Pocket Bloom

광고 전용 모바일 2D 퍼즐 게임 기획서 · 2026-10-04

## 제품의 한 문장

꽃 모양 블록을 작은 정원에 놓고 줄을 완성해, 짧은 휴식 시간마다 나만의 정원을 키우는 세로형 퍼즐 게임.

이 프로젝트의 목표는 실제 플레이와 출시 실험이 가능한 게임 한 편이다. 시장 1위와 거액 수익은 제품만으로 보장할 수 없다. 이름은 작업명이며 상표·스토어 중복 확인 전에는 확정 출시명으로 사용하지 않는다.

## 시장에서 검증할 가설

2026년 Sensor Tower 보고서는 2025년 모바일 다운로드 감소와 플레이 시간·수익의 상대적 유지, 재방문과 유지율의 중요성을 설명한다. 퍼즐 수익 성장과 다운로드 성장은 다른 지표다. 해당 보고서의 IAP 수익을 광고 매출로 해석하지 않는다.

- 근거: [Sensor Tower, State of Gaming 2026](https://sensortower.com/blog/state-of-gaming-2026)
- 가설: 익숙한 공간 퍼즐의 진입 장벽을 낮추고, 고양이와 꽃 정원의 시각적 보상으로 다시 방문할 이유를 제공한다.
- 경쟁 위험: 블록 퍼즐은 매우 혼잡한 장르다. 단순 스킨 교체만으로 경쟁 우위를 주장할 수 없다. 첫 단계의 즉시 줄 완성, 편안한 피드백, 목표 여행, 하루 한 번의 같은 문제를 하나의 흐름으로 묶는 것이 이 버전의 차별화 실험이다.
- 핵심 타깃: 짧은 휴식에 2~5분간 한 손으로 공간 퍼즐을 즐기는 일반 이용자. 연령 등급 및 아동 대상 여부는 배포 단계에서 확정한다.
- 초기 Android 우선, 한국어·영어. iOS는 별도 빌드 환경과 개인정보·추적 동의 검증 후 진행한다.

## 게임 규칙

| 항목 | 결정 |
|---|---|
| 화면 | 세로, 720×1280 논리 해상도, 실제 Safe Area에 균일 맞춤 |
| 판 | 8×8, 회전 없는 21가지 조각 |
| 공급 | 3개씩 공급, 모두 사용하면 새 묶음 |
| 조작 | 조각 드래그 또는 조각 선택 후 배치 시작 칸 터치 |
| 제거 | 가로 또는 세로 전체 8칸을 채우면 해당 줄을 동시에 제거 |
| 기본 점수 | 배치한 칸당 5점 |
| 줄 점수 | 줄당 80 × 연속 제거 콤보, 최대 5배 |
| 꽃봉오리 | 제거한 봉오리당 35점, 여행의 초기 배치에 등장 |
| 연속 콤보 | 연속 수에서 줄을 제거하면 증가, 제거하지 않은 수에서 0으로 초기화 |
| 실패 | 남은 조각을 하나도 놓을 수 없거나 제한 수 소진 |
| 승리 우선 | 마지막 수에서 목표 달성 시 성공 판정이 먼저 적용 |
| 도구 | 판마다 무료 한 수 되돌리기 1회, 새 조각 1회, 무료 힌트 |
| 체력 | 없음. 실패 후 무제한 재도전 |

첫 묶음 중 최소 하나는 현재 판에 배치할 수 있게 생성한다. 세 조각 전체를 항상 놓을 수 있다거나 매 수 정답이 존재한다고 보장하지 않는다. 색은 공간 판단에 필수적인 규칙이 아니므로 색 구분이 어려운 이용자도 플레이할 수 있다.

## 콘텐츠

### 정원 여행

36개 단계. 고정 시드와 초기 판을 사용하여 문제를 재현할 수 있다. 단계별 목표는 `320 + (단계-1)×65`점, 기본 제한 수는 `24 + 단계/3`(정수 나눗셈). 첫 단계는 가로 3칸 조각을 첫 줄 끝에 놓으면 즉시 줄이 제거된다. 1~3단계는 간단한 조각만 등장한다.

목표 달성 시 다음 단계가 열리고, 남은 수에 따라 별 1~3개가 기록된다. 마지막 36단계에는 전체 여행 완료 메시지가 나온다. 완료 단계는 언제든 다시 즐길 수 있다. 별도 광고를 봐야 다음 단계가 열리는 장벽은 없다.

### 끝없는 정원

시간 제한과 점수 목표 없이 최고 기록에 도전한다. 3개 조각을 모두 소모하는 순서와 연속 줄 제거가 주요 선택이다. 최고 점수는 기기에 저장된다.

### 오늘의 정원

UTC 날짜에서 같은 난수 시드를 생성한다. 45수 안에 1,800점을 목표로 한다. 첫 성공 시 일일 추가 씨앗 60개를 지급한다. 날짜 변경 기준은 게임 내에 표시한다. 서버가 없는 버전이므로 날짜 조작 방지, 다른 이용자 기록 검증, 글로벌 순위는 제공하지 않는다.

### 나의 정원

플레이로 모은 씨앗으로 6단계의 정원 컬렉션을 진행한다. 다음 성장 비용은 100/200/300/400/500 씨앗이다. 매일 씨앗 20개를 무료로 받는다. 씨앗은 구매하지 않으며 현금 가치가 없다. 초기 버전의 성장 표현은 이름과 피어난 꽃 배지 변화로 제공한다.

## 한 판의 흐름

홈 → 여행/끝없는 정원/오늘의 정원 → 최초 1회 조작 안내 → 배치와 줄 제거 → 목표 성공 또는 공간 소진 → 점수·씨앗·기록 저장 → 다음 단계/재도전/홈.

앱을 잠시 나가면 저장 후 일시정지한다. 저장은 JSON 임시 파일 교체와 이전 백업으로 보호한다. 돌아왔을 때 홈에서 진행 중인 판을 이어 할 수 있다. 새 모드를 시작할 때 현재 판이 교체된다는 확인 화면을 제공한다.

## 광고 전용 수익화

인앱결제, 구독, 광고 제거 상품, 유료 화폐, 가챠 상품을 넣지 않는다. 광고를 볼 수 없거나 네트워크가 없어도 일반 플레이와 여행 완료는 가능하다.

| 형식 | 노출 조건 | 보상/제약 |
|---|---|---|
| 보상형 | 실패 결과에서 이용자가 선택, 준비된 광고가 있을 때만 | 판당 1회 이어하기, 중앙 네 줄 비우기, 제한 수 +8 |
| 전면형 | 결과에서 다음 판으로 넘어가는 자연스러운 경계 | 최소 3판 완료, 세션 시작 180초 경과, 180초 간격, 보상 광고 직후 180초 제외 |
| 배너 | 사용하지 않음 | 조작 면적 확보 |

광고 보상은 SDK의 보상 콜백으로만 지급한다. 로드 실패, 표시 실패, 중복 콜백을 처리한다. 화면에 가짜 광고를 표시하거나 기다리기만 하면 광고를 봤다고 간주하는 구현은 넣지 않는다.

SDK: Unity LevelPlay Ads Mediation 9.5.1. 계정 App Key/광고 단위 ID, 실제 개인정보 동의 제공자, Android 네이티브 의존성, 실기기 Test Suite를 검증해야 수익 연결 완료로 판단한다. 현재 계정이 미설정이면 광고 SDK는 초기화되지 않고 게임은 정상 플레이된다.

## 수익 모델과 검증 기준

매출 추정식: `DAU × 1인당 실제 광고 노출 수 × 혼합 eCPM ÷ 1000`.

아래는 시장 수치가 아니라 민감도 계산용 가정이며, 보장 매출이 아니다. 달러 기준, 스토어 유입·광고 획득비·세금·운영비·국가별 편차 제외.

| 가정 | DAU | 광고 노출/DAU | 혼합 eCPM | 일 광고 매출 |
|---|---:|---:|---:|---:|
| 작은 검증 | 1,000 | 2 | $3 | $6 |
| 유지율 검증 후 확장 | 10,000 | 3 | $8 | $240 |
| 큰 규모 가정 | 100,000 | 4 | $12 | $4,800 |

수익이 나더라도 사용자 획득 비용이 더 크면 적자다. `광고 LTV > CPI + 운영비 배분`을 보수적으로 검증한 뒤에만 유료 광고 규모를 늘린다. 광고 노출 수를 무작정 늘리는 방식은 피로도와 이탈을 늘릴 수 있다.

초기 내부 목표(업계 보편 기준으로 주장하지 않음): 튜토리얼 완료 85% 이상, D1 재방문 30% 이상, D7 10% 이상, 충돌 없는 세션 99.5% 이상. 최소 300~500명의 실제 이용자 코호트와 국가·유입 경로별 결과를 보며 판단한다. 작은 표본의 좋은 숫자를 확정 성과로 홍보하지 않는다.

## 제작·운영 실험

1. 내부 검증: 36단계 무보상 승리 경로, 충돌·터치·저장·화면 비율 확인.
2. 비공개 테스트: Android 중저사양 3종 이상, 오프라인/광고 없음/광고 취소/홈 복귀 검증.
3. 첫 소프트 론치: 적은 유입으로 난이도와 D1/D7 측정. 대규모 유료 획득은 아직 하지 않는다.
4. 소재 실험: 실제 플레이 영상으로 ‘한 칸 남은 정원’, ‘3줄 동시 피우기’, ‘고양이가 쉬는 정원’ 3개 방향을 비교한다. 게임에 없는 장면을 광고하지 않는다.
5. 개선: 단계별 실패 수, 재도전, 도구 사용, 결과 이탈을 바탕으로 고정 시드와 목표를 수정한다. 버전별 시드 규칙 변경은 저장 호환 정책과 함께 관리한다.

## 구현과 출시의 경계

코드·에디터 실행·Windows 패키지·Android 빌드·Android 실기기·실제 광고·스토어 승인은 각각 별도의 증거가 필요하다. 최종 결과는 `Docs/Validation`과 `Docs/ReleaseChecklist.md`에서 확인한다. 기본 프로젝트의 기존 변경사항을 보존하며 Git 커밋·원격 업로드는 별도 요청이 있을 때 진행한다.
