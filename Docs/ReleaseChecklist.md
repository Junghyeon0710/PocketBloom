## 광고 수익 연결 — 사용자 계정 필요

사용자는 아직 광고 계정이 없으며 지금은 단말 테스트가 어렵다고 확인했다. 계정 생성과 프로젝트 연결 순서는 [AdsSetup.ko.md](AdsSetup.ko.md)에 정리했다.

- [ ] Unity LevelPlay 앱 등록, App Key, Rewarded/Interstitial ID 입력
- [ ] 대상 연령·배포 지역 결정
- [ ] 실제 서비스용 개인정보처리방침 URL, 개발자 연락처 작성
- [ ] 대상 지역과 네트워크에 맞는 CMP/동의 관리 흐름 연결
- [ ] 동의 흐름에서 `BloomAds.InitializeAfterPrivacy` 호출
- [ ] 광고 설정 `enableAds` 활성화 전에 위 항목 검증
- [x] Android 네이티브 의존성 리졸버 및 Unity Ads 어댑터 설치·빌드
- [x] AndroidManifest의 최종 병합 결과와 AD_ID 선언 검증
- [ ] 실기기에서 광고 로드/완료/취소/표시 실패/오프라인 복귀 검증
- [ ] 중복 보상 방지와 이어하기 판당 1회 검증
- [ ] 보상 광고 뒤 전면 광고 억제, 3판·180초 제한 검증
- [ ] 실제 광고 수익 보고(ILRD) 및 대시보드 금액 검증

SDK만 설치된 상태를 실제 광고 수익화 완료로 표시하지 않는다. 현재 프로젝트는 계정 미설정 시 광고를 초기화하지 않는다. 키는 계정 비밀번호가 아니지만 공개 문서에 무분별하게 복사하지 않는다.

## Android 배포

- [ ] 출시명/패키지 ID 고유성 및 상표 확인
- [ ] 개발자 소유 키스토어와 복구 가능한 서명 관리
- [ ] 릴리스 AAB, ARM64, 현재 Play 대상 API 정책 확인
- [ ] 실제 단말 3종: 성능·발열·메모리·전화/백그라운드·화면잠금
- [ ] 광고 포함/데이터 보안/콘텐츠 등급/개인정보처리방침 항목 작성
- [x] 로컬 스토어 아이콘(512×512), 소개 배너(1024×500), 한·영 등록 문구와 규격 검사
- [ ] 최종 Android 단말 스토어 스크린샷, 출시명 확정과 Play Console 업로드
- [ ] Play Console 계정 유형별 요구 테스트 및 프로덕션 접근 충족
- [ ] 비공개 테스트 피드백 반영 후 소프트 론치

Google Play 정책과 요구 API는 변할 수 있으므로 업로드 시점 공식 문서를 다시 확인한다. 스토어 공개, 계약 동의, 결제, 계정 생성은 자동으로 수행하지 않는다.

## iOS 추가 조건

Mac/Xcode, Apple 개발자 계정, 번들 ID/서명, 네이티브 의존성, SKAdNetwork, 필요 시 ATT, 실제 iPhone 테스트가 추가로 필요하다. Windows 또는 Android 빌드 성공을 iOS 검증으로 간주하지 않는다.
